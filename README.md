# Как опубликовать сайт Deadlock Atlas

Сайт готов. Он будет принадлежать твоему аккаунту GitHub. Платный хостинг и покупка домена для начала не нужны.

**Важно:** предпросмотр в чате — не постоянный публичный сайт. Чтобы люди могли заходить по постоянной ссылке и скачивать приложение, выполни шаги ниже.

## Что скачать из чата

1. `Deadlock-Atlas-Website.zip` — файлы сайта. Распакуй архив на своём компьютере.
2. `Deadlock-Atlas.exe` — приложение версии 1.0.1 с твоим именем.
3. `Deadlock-Atlas.sha256` — контрольная сумма приложения (можно прикрепить к релизу рядом с EXE).

EXE не включён в ZIP сайта. Так его не придётся скачивать повторно, и сайт останется небольшим.

## 1. Создай репозиторий

1. Войди в свой GitHub.
2. В правом верхнем углу нажми **+ → New repository**.
3. В поле **Repository name** введи `deadlock-atlas`.
4. Выбери **Public** — публичный репозиторий для бесплатной публикации Pages.
5. Включи **Add a README file** и нажми **Create repository**.

Здесь и далее `USERNAME` — твой логин GitHub, а не имя профиля Maksim Mishunov.

## 2. Загрузи файлы сайта

В репозитории открой **Add file → Upload files**.

Перетащи **содержимое распакованного архива**, не сам ZIP и не внешнюю папку:

```text
index.html
style.css
site.js
config.js
assets/
.nojekyll
README.md
```

Нажми **Commit changes**. В корне репозитория должен находиться именно `index.html`.

Если проводник скрывает `.nojekyll`, сайт с этими обычными HTML/CSS/JS-файлами будет работать и без него.

**Не загружай EXE в раздел Code.** Крупные файлы приложения нужно размещать в Releases (следующий шаг). Для сайта не нужны исходники Electron, `node_modules`, пароль или токен.

## 3. Опубликуй приложение в Releases

1. Открой страницу своего репозитория.
2. Справа найди **Releases**, затем **Create a new release**. Также можно открыть:
   `https://github.com/USERNAME/deadlock-atlas/releases/new`
3. В поле тега создай **`v1.0.1`**; целевая ветка — `main`.
4. Название релиза: **Deadlock Atlas 1.0.1**.
5. В описание можно вставить:

   > Неофициальный справочник Deadlock для Windows 10/11 x64.
   > Создатель — Maksim Mishunov.
   > 39 героев, 117 сборок, 173 предмета. Работает офлайн.
   > Снимок игровых данных: 04.10.2026. Автообновления нет.
   > Приложение без цифровой подписи. Проверяйте файл перед запуском.

6. В область **Attach binaries** перетащи `Deadlock-Atlas.exe` и, при желании, `Deadlock-Atlas.sha256`.
7. Дождись полной загрузки файлов. Имя приложения должно быть **точно `Deadlock-Atlas.exe`**.
8. Не отмечай релиз как prerelease. Если есть поле **Set as the latest release**, включи его.
9. Нажми **Publish release**, не сохраняй только черновик.

Проверочная ссылка на скачивание:

```text
https://github.com/USERNAME/deadlock-atlas/releases/latest/download/Deadlock-Atlas.exe
```

Если при загрузке браузер автоматически добавил к имени `(1)`, переименуй локальный файл обратно перед публикацией.

## 4. Включи сайт

1. В репозитории открой **Settings → Pages**.
2. В разделе **Build and deployment** выбери **Source: Deploy from a branch**.
3. Выбери ветку **main**, папку **/ (root)**.
4. Нажми **Save**.
5. Подожди завершения публикации. Статус можно посмотреть во вкладке **Actions** или на странице **Pages**. Это может занять несколько минут.

Сайт появится по адресу:

```text
https://USERNAME.github.io/deadlock-atlas/
```

На стандартном GitHub Pages кнопка сама определит твой логин и имя репозитория из адреса сайта. В `config.js` ничего менять не нужно.

## 5. Проверь перед тем, как делиться ссылкой

- Открой сайт в приватном окне браузера, без входа в GitHub.
- Нажми «Скачать для Windows», затем «Скачать .exe».
- Убедись, что загружается `Deadlock-Atlas.exe`, а не страница 404.
- Проверь сайт на телефоне и переключение скриншотов «Герои / Сборка».
- После этого отправляй друзьям адрес сайта.

Если скачивание даёт **404**, проверь: репозиторий публичный, релиз опубликован и не prerelease, файл загружен с точным именем, latest-релиз содержит этот файл.

## Свой домен — позже

При переходе на собственный домен автоматическое определение репозитория по `github.io` перестанет работать. В `config.js` укажи:

```js
window.ATLAS_SITE = { repository: 'USERNAME/deadlock-atlas' };
```

Подключение домена и DNS — отдельный шаг; сейчас это не требуется.

## Когда выйдет новая версия

1. Создай новый опубликованный релиз, например `v1.0.2`.
2. Загрузи новую сборку с тем же именем `Deadlock-Atlas.exe` и её новую SHA-256.
3. Назначь релиз последним (latest).
4. Обнови в `index.html` номер версии, размер, дату данных, контрольную сумму и описания изменившихся возможностей. При необходимости замени скриншоты в `assets`.

Ссылка `/releases/latest/download/Deadlock-Atlas.exe` будет вести на файл из последнего релиза, но текст сайта нужно обновлять отдельно. Это не механизм автообновления установленного приложения.

## О безопасности и правах

На сайте оставлено предупреждение об отсутствии цифровой подписи. Само размещение на GitHub не убирает предупреждения Windows и не является проверкой безопасности файла.

Игровые изображения и названия принадлежат правообладателям. На сайте есть указание на неофициальный характер проекта и источник данных Deadlock API. Авторские права на игровые материалы не переходят к создателю сайта.

Пароль GitHub или токен никому передавать не нужно. Для дальнейшей помощи достаточно ссылки на публичный репозиторий.
