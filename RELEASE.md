# Как выпустить новую версию

Шпаргалка по релизу Deadlock Atlas: данные, приложение, релиз на GitHub и сайт.

## Что где лежит

- `data/*.json` — данные, которые встраиваются в приложение (герои, предметы, сборки, герои на голосовании).
- `tools/fetch_raw.py`, `tools/build_dataset.py` — сборка этих данных из Deadlock API.
- `.github/workflows/atlas-data.yml` — автоматический снимок данных в служебную ветку `atlas-data-raw`.
- `index.html`, `site.js`, `style.css`, `README.md` — сайт (GitHub Pages собирается из ветки `main`, каталог `/`).

## Шаг 1. Обновить данные

```bash
python3 tools/fetch_raw.py --out data/raw
python3 tools/build_dataset.py --raw data/raw --out data
```

Либо: Actions → **atlas-data** → *Run workflow* — воркфлоу сам скачает снимок и
сложит результат в ветку `atlas-data-raw` (оттуда `data/*.json` можно скопировать).

Проверки перед сборкой приложения:

- `data/meta.json` → `counts`: героев 40, предметов 173, сборок 120;
- в `data/heroes.json` есть новые герои (Буся, Крысиный король) с четырьмя способностями;
- в `data/builds.json` у каждого героя ровно три сборки, есть `id` и группы покупок;
- в `data/upcoming.json` — четыре героя на голосовании и даты релизов.

## Шаг 2. Собрать приложение

Делается в проекте самого приложения (вне этого репозитория):

1. Подставить в сборку обновлённый каталог `data/` из этого репозитория.
2. Поднять внутреннюю версию приложения до **1.0.2** — её видно в окне приложения
   и упоминает сайт.
3. Собрать `Deadlock-Atlas.exe`.
4. Проверить вручную: в списке 40 героев, Буся и Крысиный король открываются,
   у предметов и способностей русские описания, у каждого героя три сборки,
   ID сборки копируется.

## Шаг 3. Опубликовать релиз на GitHub

1. Releases → **Draft a new release**.
2. Тег — `v1.0.2` (site.js отбрасывает ведущую `v`, так что подойдёт и `1.0.2`).
   Target — ветка, в которую влиты обновления сайта и данных (обычно `main`).
3. Заголовок — `Deadlock Atlas 1.0.2`.
4. Описание — заметки о релизе (шаблон ниже).
5. Прикрепить файл **`Deadlock-Atlas.exe`** — имя должно совпадать: по нему
   работают кнопка скачивания и автоподстановка контрольной суммы.
6. Опубликовать и убедиться, что релиз стал **Latest** (не черновик и не
   pre-release) — иначе `/releases/latest/download/Deadlock-Atlas.exe` отдаст старую версию.

## Шаг 4. Обновить сайт

1. Влить рабочую ветку в `main` (Pull Request → Merge). Pages пересоберётся сам.
2. Открыть https://warfaiser.github.io/Deadlock-Atlas/ и проверить:
   - в карточке скачивания версия и SHA-256 подтягиваются с последнего релиза
     автоматически (их подставляет `site.js` через GitHub API);
   - кнопка «Скачать .exe» ведёт на `/releases/latest/download/Deadlock-Atlas.exe`;
   - счётчики на странице (40 героев, 120 сборок, 173 предмета) и блок
     «Новые герои уже в атласе» совпадают с содержимым релиза.
3. Проверить контрольную сумму у себя (PowerShell):

```powershell
Get-FileHash .\Deadlock-Atlas.exe -Algorithm SHA256
```

Сумма должна совпасть с той, что показывает сайт. Если JS отключён, в HTML
останется текст заглушки — тогда можно вписать сумму руками в
`<code id="checksum">` в `index.html`.
